# VoiceFrame 项目构建计划

日期：2026-10-29。面向个人创作者和教学视频制作；第一版为单用户、自托管工作台。

## 1. 产品目标与验收

从一个原始视频出发，在同一个网页完成字幕导入/提取、逐句读法编辑、音色试听、参考声音克隆、时间校准、短片预览及最终视频下载。所有任务进度、失败原因及可重试项必须可见。不能以模拟音频冒充生成结果。上线不承诺未经测试的 GPU 性能。

六步主流程：素材 → 字幕 → 声音 → 发音 → 预览与同步 → 导出。项目可关闭后重新打开；音色与读法修改使预览审批失效；最终生成只允许使用已试听确认的同一配置版本。

## 2. 用户体验与视觉设计

- 桌面三栏工作区：左侧项目/步骤，中间视频与字幕时间线，右侧当前步骤设置。窄屏改为纵向布局。
- 浅暖灰底、深墨色文字、蓝紫主色；充足留白，真实状态代替装饰性的统计数据。
- 空状态提供明确动作；上传进度、任务阶段、错误建议、取消/重试、保存状态始终可见。
- 字幕列表包含原文、实际读法、开始/结束时间；点击跳转视频。原文与 spoken_text 分开，数学公式/多音字规则只影响合成，不修改画面文字。
- 同步控制使用“正数 = 声音延后”；可以在当前视频帧与所选字幕之间设置锚点自动算偏移。严禁给所有视频默认套用本案例的 2.12 秒。
- 试听支持音色短句和带画面的时间段预览；确认预览后开放最终生成。
- 表单有标签、键盘焦点、错误提示；动态任务状态使用 aria-live；不依赖颜色表达错误。

Intel Mac 支持明确延后，不属于第一版验收范围。代码、注释与 API 字段使用英文；提供 README.md 英文版和 README.zh-CN.md 中文版，界面支持中英文切换。

## 3. 技术架构

FastAPI + Pydantic API；原生 ES modules / HTML / CSS 前端，避免跨平台 Node 构建成为本地启动门槛。SQLite WAL 保存项目、配置、任务快照和状态；本地 data 目录保存媒体、缓存和结果。单进程单工作线程串行执行 GPU 任务，防止 M3 18 GB 同时加载多个模型造成内存压力。FFmpeg/FFprobe 负责媒体验证、字幕轨提取、转码和音轨合成。

模型适配层：

| 平台 | 引擎 | 说明 |
|---|---|---|
| Apple Silicon Mac | MLX-Audio | Qwen3-TTS 1.7B 4bit，按需加载 Base / CustomVoice |
| Windows / Linux NVIDIA | PyTorch + qwen-tts | CUDA 自动检测，使用官方 Qwen Base / CustomVoice |
| Windows / Linux CPU | PyTorch CPU | 慢速备用路径，不承诺实时 |
| AWS | Linux NVIDIA EC2 + Docker | 与 PyTorch 引擎共享代码；不使用 MLX |

模型版本、引擎、文字、seed、参考录音哈希与参考文字共同形成音频缓存键；时间偏移不影响原始音频缓存。一次只持有一个 TTS 模型。参考音色不叠加预设 speaker。

## 4. 字幕与发音

1. 上传 SRT / WebVTT：验证时间、顺序、重叠、空内容、文件大小与视频范围。
2. 检测封装字幕轨：FFprobe 列出轨道，选择并抽取文本轨；图像字幕提示使用 OCR。
3. 画面烧录字幕：用户选择底部裁剪区域，Tesseract 按固定采样间隔 OCR，合并连续相同文字；结果必须人工校对，时刻精度受采样间隔限制。
4. 原声转写：可选 faster-whisper，明确标为“原声转写”，不冒充画面字幕识别；需人工校准。
5. 特殊读法：项目词典按最长匹配一次替换，不递归替换；逐句 spoken_text 优先。规则预览显示实际送入模型的文本。
6. 原画面保持；首版不提供无痕消除烧录字幕或口型同步。不能承诺复杂公式自动准确理解。

## 5. 任务与媒体流水线

上传 → 安全命名与 FFprobe → 项目配置 → 保存版本 → 创建不可变任务快照 → 单 worker 领取 → 逐句合成/缓存 → FFmpeg 适度调速 → 按 cue 起止写入静音时间线 → 原画面合成。

- 默认最大加速 1.15，可调至 1.25；短句补静音。无法容纳时报告 cue、原始时长、可用时长、需要的倍速；不裁掉讲话、不自动缩写。
- FFmpeg 调速结果按真实采样数检查，允许逐步微调；到达上限仍超时则返回结构化失败详情。
- 预览可选开始秒与长度，选取相交字幕完整范围；最终导出使用真实媒体时长，不能硬编码 342 秒。
- 输出 MP4(H.264/AAC)、WAV、校准后 SRT。默认替换原音轨；保留背景音乐需独立音乐轨，不直接混入原讲解。
- 任务可取消（生成当前句结束后生效）、失败可重试并复用缓存。进程重启将 running 标记 interrupted；用户明确重试，不假装任务仍运行。

## 6. API / 数据模型

- Project: id, name, created_at, revision, video metadata, cues, settings, pronunciation rules, reference metadata, approved_revision。
- Cue: id, start, end, text, spoken_text。
- Job: id, project_id, kind, snapshot, status, progress, stage, error, result, cancellation flag。
- /api/projects CRUD；/video、/subtitles、/reference 上传；/jobs 创建、查询、取消和重试；/approve 预览确认；/media 受保护文件流；/api/system 环境诊断。
- 保存采用 revision 乐观锁；避免 OCR 任务覆盖用户在其运行期间的编辑。上传内容与结果不能通过任意路径访问。

## 7. 本地安装与 GitHub

- Mac/Linux: start.sh；Windows: start.ps1 + start.bat。自动创建虚拟环境、安装核心依赖；TTS 可选安装脚本，避免第一次打开网页就强制下载数 GB 模型。
- 复用用户现有 QwenVoice Python 环境：通过 VOICEFRAME_PYTHON 指定解释器。项目启动时显示 FFmpeg、引擎包、OCR / ASR 状态。
- README 提供三平台步骤与常见故障处理；Git 忽略模型、视频、缓存、个人参考录音和 .env。
- 默认创建个人账号下私有 voiceframe 仓库；当前连接器缺少 create-repository 能力，提供 gh 创建/推送脚本；不伪造仓库地址或宣称已创建。
- GitHub Actions 执行纯逻辑/API/FFmpeg 测试；重型模型 smoke tests 单独在对应硬件运行。

## 8. AWS 部署

第一阶段单机 GPU EC2 + Docker Compose + Caddy TLS + 加密 EBS 持久数据。Terraform 提供网络、安全组、SSM IAM、实例与磁盘模板；GPU AMI ID 由部署者选择当前区域支持的镜像。不开公网 SSH，不自动创建付费资源。

网页通过共享访问密钥登录，HttpOnly 会话 cookie；公开部署强制设置高强度密钥和 HTTPS。所有媒体和任务 API 都需要认证。此版本不是多租户 SaaS；多人权限、账单、配额、S3/队列分离部署留作第二阶段。备份 data 目录和 SQLite 使用一致性备份；备份不包含缓存即可重算。

## 9. 开发顺序

M0：计划、仓库结构、依赖与启动脚本。
M1：项目数据库、媒体上传、SRT/VTT、配置和发音规则 API。
M2：双引擎 TTS、持久任务、缓存、取消重试、时间线合成。
M3：三栏工作台，所有按钮连接真实 API，进度与错误处理。
M4：字幕轨/OCR/ASR、校准锚点、审批与最终导出。
M5：安全边界、自动测试、浏览器 QA、跨平台说明和 AWS 模板。

## 10. 验证矩阵与交付边界

- 单测：字幕解析/重叠、读法替换、缓存失效、偏移正负、边界、配置审批失效。
- API：上传格式限制、目录穿越、认证、项目隔离（单用户项目范围）、任务快照、冲突。
- 集成：使用可辨识的合成测试音验证 FFmpeg 时间线、字幕偏移、超时不截断、预览切片和最终视频媒体信息。测试音只在测试中使用。
- 前端：新建项目、上传、编辑、保存、试听任务状态、失败与重试、窄屏、键盘焦点。
- Mac MLX、Windows NVIDIA、Linux NVIDIA 的真实声音生成需要对应硬件验证，交付时清楚标注已测/未测。AWS 模板验证不等于已部署。

## 11. 后续可选增强

强制字词对齐、连续段落合成后拆句、自动 OCR/SRT 锚点匹配、多人音色、可视化波形、独立配乐、S3 + PostgreSQL + 队列、OIDC、多用户与项目分享。先保证第一版任务可追踪和结果可复现，再扩大部署规模。
